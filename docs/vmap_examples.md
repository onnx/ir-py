# Practical independent batching

{py:class}`~onnx_ir.passes.common.VmapPass` turns a single-example computation
into an ordinary ONNX tensor graph. Its generated API documentation describes the
supported operators, controls, and restrictions.

The runnable script [`examples/vmap.py`](https://github.com/onnx/ir-py/blob/main/examples/vmap.py)
builds two complete examples, prints their **actual before/after ONNX graphs**,
and saves both binary models and readable ONNX text:

```sh
python examples/vmap.py --output-dir vmap_models
```

Each example transforms its model **once**, reloads the saved models, and checks
numerical equivalence with stacked independent executions at batch sizes **1, 3,
and 7**. No ONNX Runtime installation is required; the script uses ONNX's
reference evaluator. Open the saved `.onnx` models in your ONNX graph viewer, or
compare the corresponding `.txt` files.

## Convolutional image classification

The source classifier applies `Conv → Relu → GlobalAveragePool → Flatten →
Add → Gemm → Softmax`. Learned weights are shared initializers; a runtime channel
calibration vector is also shared. The pass is invoked with
`in_axes=(0, None), out_axes=(0,)`.

| Value | Before | After |
| --- | --- | --- |
| `image` | `[1, 1, 8, 8]` (NCHW) | `[B, 1, 1, 8, 8]` |
| `calibration` | `[4]` | `[4]` (shared) |
| `probabilities` | `[1, 3]` | `[B, 1, 3]` |

The new B axis is **not** the classifier's existing N axis. Around convolution
and pooling, generated `Shape`, `Gather`, `Mul`, `Concat`, and `Reshape` nodes
merge B with N and restore them afterward. Flatten keeps B separate, calibration
broadcasting inserts singleton example dimensions, and Softmax remains over the
three classes, not over B.

## Recommendation from pooled session history

The source graph gathers three history embeddings from a shared table, averages
them, normalizes the user and candidate vectors, and computes cosine similarity
with vector MatMul. It returns both the normalized user representation and score.
The pass uses `in_axes=(-1, 0, None), out_axes=(-1, 0)`.

| Value | Before | After |
| --- | --- | --- |
| `history_ids` | `[3]` | `[3, B]` (trailing mapped axis) |
| `candidate` | `[4]` | `[B, 4]` (leading mapped axis) |
| `embedding_table` | `[16, 4]` | `[16, 4]` (shared) |
| `user_embedding` | `[4]` | `[4, B]` |
| `cosine_score` | scalar | `[B]` |

The transformed graph transposes history IDs to its internal leading-batch
layout. Gather retains pairing between each user's IDs and the shared table.
The history reduction and normalization axes shift so they never mix users.
Vector MatMul receives explicit `Unsqueeze` / `Squeeze` adapters, and a final
transpose places the representation's output batch axis last.

Inspect `recommendation.single.onnx` / `recommendation.batched.onnx`, or their
text counterparts. The embedding table can be changed at runtime without
retransforming the graph.
